## 关键兼容问题与处理

- Codex 的 `app-server daemon version` 显示本机未运行共享控制 socket；CLI 提供该命令不能证明它接管了桌面会话。
- 社区原生管道使用普通独立 Node 进程只读探测时被关闭；宿主日志记录 `untrusted-code-signing-identity`。保留了此身份边界，未采用替换身份或更改签名的方式。
- ZCode 初始默认超时约 30 秒，造成模型重新调用。修复位于宿主支持的项目配置字段，随后用一次 80 秒调用及宿主日志验证。
- 开发中 MCP 子进程曾保留旧 SDK 元数据处理代码，出现通用工具错误。修正 SDK 2 的字典元数据契约，并仅重载本次测试子进程；随后原生任务绑定和长等待通过。
- 服务对 HTTP 断连显式取消等待任务；避免已经取消的桌面调用仍挂到等待上限，影响正常退出。消息保留，可按原游标恢复。

## 模型判断

初版类别说明下，Qwen3 1.7B 的建议为 5/8 符合预设类别。明确 retry、wait、stop、inspect、clarify 的实际操作含义后复测为 6/8；授权到期两例仍不符合要求。很多解释接近原事实复述，尚未证明比程序直接给出的错误信息更有帮助。因此本版保留可配置模型接口，暂不选择默认模型、不自动执行模型建议。

这是一小组开发样本，不是通用准确率或安全评测。云端 API、其他本地模型及自动模型安装界面尚未验证。已下载权重与应用源码独立管理。

## 已知边界

- 本版使用主动 MCP 订阅；尚不能自动唤醒任意闲置桌面任务。
- 已核验 ZCode 远程控制的原桌面任务附接与提交调用链；尚未进行本机配对和真实唤醒测试，详见 [自动唤醒核验](ZCODE_WAKEUP_RESEARCH.md)。
- 原生任务绑定位于本机 MCP 适配器，防止多个正常桌面任务混用端点。拥有同一操作系统账户和凭据的进程不构成相互安全隔离。
- 写入锁仅约束受控接口，未宣称拦截客户端原生编辑、任意 shell 写入或所有 Hooks 路径。外部写入的最终检查竞态仍存在。
- 模型建议不能改变程序的授权、过期、去重和文件规则。当前推荐模型质量不足，因此默认不启用。
- 开源准备范围是本地源码、许可证和说明，尚未公开发布。
